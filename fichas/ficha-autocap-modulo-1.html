🏗️ 1. La frase maestra

M.E.T.A.S es una aplicación web estática y offline-first que se distribuye por tres frentes (web, PWA y APK Android) desde un mismo código, y usa Supabase como nube para lo único que de verdad necesita servidor.
TérminoQué significa en este proyecto
Web estáticaArchivos HTML, CSS y JS entregados tal cual por GitHub Pages. Ningún programa arma páginas en un servidor.
Offline-firstEl dispositivo primero: los datos viven en localStorage y la nube es copia, no requisito.
PWALa misma página, instalable, que abre sin conexión gracias al service worker.
APKEl mismo código empaquetado con Capacitor como aplicación firmada de Android.
SupabasePostgreSQL como servicio: funciones RPC como única puerta, RLS por fila y deduplicación por evento_id.

🔁 2. El viaje de un dato

  1. El dato nace en el dispositivo (una evaluación terminada, un análisis generado).
  2. Guardado local inmediato en localStorage: un corte de luz ya no pierde nada.
  3. Una copia entra al outbox con su evento_id único.
  4. Con internet, el lote sube a Supabase; sin internet, espera y se reintenta solo.
  5. El maestro lo consulta en su panel y la familia en el asistente, cada quien con su clave.
La idea que hay que defender: los tres frentes no son tres desarrollos. Un solo código se entrega de tres maneras, y por eso una sola persona puede mantener el sistema completo.

✅ Pauta de respuestas

B. Completa

  1. GitHub Pages, con el archivo CNAME.
  2. localStorage.
  3. Outbox.
  4. evento_id.
  5. Capacitor.

C. Verdadero o falso

  1. Falso. No hay servidor propio: el frontend es estático y la nube es un servicio.
  2. Falso. Es offline-first: la copia local abre y guarda sin red.
  3. Falso. Es la clave pública (anon): solo permite lo que RLS y las funciones RPC autorizan. La peligrosa, service_role, jamás sale del servidor.
  4. Falso. Es el mismo código, empaquetado con Capacitor.

Simulacro: respuestas modelo

1) No hay servidor propio. El frontend es estático en GitHub Pages y lo único que exige servidor lo hace Supabase como servicio. Menos piezas propias significa menos que se cae, menos que mantener y un costo cercano a cero, que es la condición para que esto sea sostenible en una escuela pública.

2) La aplicación es offline-first: abre y guarda sin red porque el service worker guarda la copia local y los datos viven en el dispositivo. Una caída de la nube afecta la sincronización, no la clase; cuando vuelve, el outbox reenvía y el evento_id evita duplicados.

3) Esa clave es la pública, y va en el código a propósito: solo puede hacer lo que autorizan las reglas RLS y las funciones RPC. Las escrituras exigen cuenta docente y hay límite por IP real. La clave con poder, service_role, no está en el repositorio ni llega al navegador.
